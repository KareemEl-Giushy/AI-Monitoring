Stop runaway AI agents before they burn your budget.

The circuit breaker for AI agents, by Team MarsadOps: a Go reverse proxy with pluggable breakers that sits between your agents and any OpenAI-compatible API. It stops tool-call loops, failing tools, request floods and degenerate streams, and exports every decision to Prometheus and Grafana.

A runaway agent doesn’t crash. It keeps going.

Autonomous agents fail by repeating themselves. Every request looks valid on its own, so nothing errors and nothing alerts, while the tokens keep flowing until someone reads the bill.

  • CB-01

    Tool loops with mutated arguments

    The agent runs the same search again with “(attempt 1)”, then “(attempt 2)”, and gets the same answer each time. Every call is slightly different, so each one looks like new work.

  • CB-03

    Error storms

    A tool keeps failing and the agent keeps calling it, feeding each failure back into the next attempt.

  • CB-04

    Request floods

    A tight loop fires requests far faster than any person would.

  • CB-05

    Degenerate output

    The model collapses into repetitive text such as “! ! ! !” or the same apology, and keeps streaming it.

  • CB-06

    Injected instructions

    A web page or tool result tells the agent to “ignore all previous instructions”.

  • OBS

    Silent token burn

    None of the above raises an error on its own, so spend climbs quietly in the background.

Why rate limiters and exact-hash dedupe miss loops

Rate limiter

Counts requests, not behavior. A loop running at a steady pace stays under the limit forever, while a legitimate burst of work gets throttled.

Exact-hash dedupe

Change one character and the fingerprint is unrelated, so the loop looks like fresh work.

  • …crashloop fix (attempt 0)
    sha256 436ada7dc45f…
  • …crashloop fix (attempt 1)
    sha256 dd1fc3c6b2dd…

AI Agent Circuit Breaker

Compares what the agent is doing. After masking counters, timestamps and IDs, the two calls share most of their character 3-grams. If the tool also keeps returning the same result, they count as one repeated action.

    0.887 ≥ 0.8 → same call
  • simhash: 4 bits apart

One proxy between your agents and the model API

Point your agent’s base URL at the breaker. The proxy is a small Go kernel: it parses each request, runs it through a pipeline of plugins and enforces what they decide. Everything else goes through unchanged to any OpenAI-compatible upstream, here the LiteLLM gateway, which routes to Groq, Gemini or Ollama. The proxy exports its own metrics; LiteLLM exports its own.

What happens to every request

  1. Identify the sessionFrom the X-Session-ID header; otherwise from a hash of the API key plus the conversation’s opening system and user messages.
  2. Run the request hooksPlugins run in config.yaml order. Velocity counts the request and policy scans the new user and tool messages. The first BLOCK returns 403, the first THROTTLE 429, before the model is called.
  3. Check the tool resultsThe newest tool messages go to OnToolResult: error_acc counts consecutive failures, and the loop plugins note whether each result changed.
  4. Forward upstreamPath, query and headers go through unchanged, and the global sliding window records the request. If the upstream is down, the agent gets a JSON 502.
  5. Check each tool call in the replyEvery tool call the model returns goes to OnToolCall. A repeat of an earlier call with an unchanged result becomes a 403 before the agent can run it.
  6. Hold back streamed tool callsIn a stream, tool-call events are held until the call is complete and checked. A blocked call is never sent: the stream ends with an error event instead of [DONE].
  7. Check streamed textEach text delta goes to OnStreamChunk with the rolling entropy of the last 1 KiB. A degenerate stream is cut and the upstream connection closed.
  8. Record everythingEvery hook call is timed and counted for Prometheus, incidents go to your webhooks, and each turn is saved to a conversation JSON file.

Six breakers on one panel

Each plugin watches for one way an agent runs away. The kernel runs them in the order listed in config.yaml and enforces the first BLOCK or THROTTLE. Values below are the shipped defaults; most can be set per plugin in config.yaml. Flip a lever to see what that breaker reports when it trips.

    CLOSED

    Tool-call loop: SimHash

    plugins/simhash

    The same tool called again with near-identical arguments while its result stays the same. Arguments are normalized first: keys sorted, and numbers, timestamps, IDs and long tokens masked. Then a 64-bit SimHash over 3-character shingles is compared.

    Trips at
    The 3rd call within 60 s that is ≤ 3 bits apart and gets the same result. Arguments of 256+ characters must match exactly.
    Action
    BLOCK: 403, or an error event in a stream
    Reports
    TOOL_CALL_REPETITION_LOOP
  • CB-02
    CLOSED

    Tool-call loop: Jaccard

    plugins/jaccard

    A second similarity test on the same normalized arguments: the share of character 3-grams two calls have in common. It catches reworded retries that SimHash scores as further apart, like a changed attempt number.

    Trips at
    The 3rd call within 60 s with Jaccard ≥ 0.8 and the same result
    Action
    BLOCK: 403, or an error event in a stream
    Reports
    TOOL_CALL_REPETITION_LOOP
  • CB-03
    CLOSED

    Tool error storm

    plugins/error_acc

    A failing tool the agent keeps retrying. Each tool result is judged by its structure (an error field, "status":"failed", "ok":false) or by text that starts like an error. A success resets the count.

    Trips at
    3 consecutive errors from one tool in a session, then stays open for a 60 s cooldown
    Action
    BLOCK: 403 before the model is called
    Reports
    TOOL_ERROR_ACCUMULATION

    CLOSED

    Request flood

    plugins/velocity

    A tight loop hammering the API. Requests are counted per session over the last second, and per endpoint path over the last minute.

    Trips at
    More than 10 requests in 1 s, or more than 50 to one path in 60 s
    Action
    THROTTLE: 429 with Retry-After: 5
    Reports
    HIGH_RPS_DETECTED
    ENDPOINT_REPEAT_EXCEEDED
  • CB-05
    CLOSED

    Degenerate stream

    plugins/entropy

    The model collapsing into noise or repeating itself in a streamed reply. The plugin reads the decoded text deltas, not the SSE framing. Non-streaming replies are not checked.

    Trips at
    After 256 bytes: entropy of the last 1024 bytes below 1.5 bits/byte, or fewer than 15% distinct 8-character sequences
    Action
    BLOCK: the stream ends with an error event, no [DONE]
    Reports
    MODEL_DEGENERATION_LOW_ENTROPY
    MODEL_DEGENERATION_REPETITION
  • CB-06
    CLOSED

    Prompt-injection tripwire

    plugins/policy

    Well-known injection phrasings in the newest user and tool messages, after lowercasing and collapsing whitespace. It is a tripwire, not a full defence: paraphrases get through.

    Trips at
    Any of 3 default patterns: “ignore previous instructions”, “reveal your system prompt”, “you are now DAN” and their close variants
    Action
    BLOCK: 403 before the model is called
    Reports
    DECLARATIVE_POLICY_VIOLATION
403 BLOCK
Stops the request, or replaces a tool call in the model’s reply, with an OpenAI-style error and an SRE incident.
429 THROTTLE
Slows the agent down with Retry-After: 5 and the same incident body.
SSE Stream cut
A streamed reply already sent 200, so it ends with one error event, and the upstream stream is closed.

Plus WASM extensions. The shipped tool-guard extension blocks dangerous commands, URLs outside an allowlist and leaked credentials in tool calls and results (TOOL_GUARD_*). If a plugin itself errors or panics, the fail policy decides: open (default) lets the request through, closed blocks it with PLUGIN_ERROR_FAIL_CLOSED.

Write your own breaker

A breaker is a plugin. The kernel calls its hooks and enforces the verdict it returns: ALLOW, BLOCK, THROTTLE or MUTATE. Write a native Go plugin to see every hook, or a sandboxed WASM extension you can load into a running proxy.

Native Go plugin .so

  • OnRequest before the model is called (the only hook where MUTATE rewrites the body)
  • OnToolCall for each tool call the model returns
  • OnStreamChunk for each streamed text delta, with the rolling entropy
  • OnResponse after the reply, observe only
  • Optional: OnToolResult for tool results, Reset for the reset API

Build it with the same Go version and flags as the proxy. Native plugins need Linux or macOS and load at startup.

plugins/myguard/main.go
package main

import (
	"net/http"
	"strings"
	"time"

	"circuit-breaker-proxy/inspector"
)

type Guard struct{}

// The loader looks up this exported symbol.
var Measure inspector.Measure = &Guard{}

func (g *Guard) Name() string                          { return "NoDropTable" }
func (g *Guard) Init(cfg map[string]interface{}) error { return nil }

func (g *Guard) OnToolCall(ctx *inspector.RequestContext, tool, args string,
	isErr bool, errMsg string) (*inspector.Verdict, error) {
	if tool == "run_sql" && strings.Contains(strings.ToLower(args), "drop table") {
		return &inspector.Verdict{Action: inspector.VerdictBlock, Incident: &inspector.SREIncident{
			IncidentID: inspector.GenerateIncidentID(), Timestamp: time.Now(),
			CircuitState: "OPEN_TRIPPED", FailureClass: "SQL_DROP_TABLE", ToolName: tool,
			Mitigation: "Blocked a DROP TABLE", ActionRequired: "Ask a human to run it",
		}}, nil
	}
	return nil, nil // nil = ALLOW
}

// Hooks this breaker doesn't use: return nil (ALLOW).
func (g *Guard) OnRequest(*inspector.RequestContext, *http.Request, *inspector.OpenAIRequest) (*inspector.Verdict, error) {
	return nil, nil
}
func (g *Guard) OnStreamChunk(*inspector.RequestContext, []byte, uint32, float64) (*inspector.Verdict, error) {
	return nil, nil
}
func (g *Guard) OnResponse(*inspector.RequestContext, *inspector.RecordedResponse) (*inspector.Verdict, error) {
	return nil, nil
}
func (g *Guard) Close() error { return nil }
build and enable
go build -buildmode=plugin -o plugins/myguard.so ./plugins/myguard
# add  - "./plugins/myguard.so"  under plugins: in config.yaml, then restart

WASM extension .wasm

  • Exports allocate and deallocate, plus any of on_request, on_tool_call, on_tool_result and on_init
  • Sandboxed in wazero: 10 MiB of memory, 250 ms per call by default, no filesystem
  • Hot-load with POST /api/v1/measures/load (API token required). Hot-loaded extensions get no config and join the end of the pipeline
  • Worked example: extensions/tool-guard with blocked_commands, allowed_domains and block_secrets

WASM extensions don’t receive stream chunks or responses. To give one a config, list it in config.yaml instead of hot-loading it.

the ABI, in Go 1.24+

//go:wasmexport deallocate

//go:wasmexport on_tool_call

// result: {"Action":"BLOCK","Incident":{"failure_class":"...","mitigation":"...",
//          "action_required":"..."}}

Every trip comes with an incident report

The agent gets a structured error it can act on instead of a silent failure, and whoever is on call can get the same incident through a webhook: what tripped, the evidence, and what to do next.

403 Blocked
A BLOCK before the model is called (policy, error storm), or on a tool call in the model’s reply (loops, tool-guard). The body is JSON with error and sre_incident.
429 Throttled
A THROTTLE from the velocity plugin, with Retry-After: 5 and the same body.
SSE Stream cut
A streamed reply has already sent 200. The proxy drops any held-back tool-call events, sends one final data: {error, sre_incident} event, closes the upstream stream and never sends [DONE].
  • error.code is the failure class in lowercase and error.type is circuit_breaker, so OpenAI-compatible clients treat it as an API error.
  • failure_class names what tripped; details holds the plugin’s evidence.
  • mitigation and action_required say what happened and what to change.

Run it locally

The proxy is a Go binary plus its plugin files. Each observability stack is one docker compose setup. Run them on their own, or chain them.

Circuit breaker

Needs Go 1.26.6 or newer, Linux or macOS, and a C compiler (cgo builds the plugins).

shell
git clone https://github.com/KareemEl-Giushy/AI-Ciurcit-Breaker.git
cd AI-Ciurcit-Breaker
./test.sh                  # builds the plugins and ./circuit-breaker, then runs the tests
# or build only: cd plugins && make && cd .. && go build -o circuit-breaker .
cp config.example.yaml config.yaml
# edit config.yaml: set server.target_url to your API, e.g. "http://localhost:4000"
./circuit-breaker
  • Start it from the repository root: the plugin paths in config.yaml are relative.
  • Check the startup line Active measures: lists six plugins. “No plugins loaded” means traffic passes unprotected.
  • Point your agent at http://localhost:8080/v1 and send an X-Session-ID header per agent run.
  • Always set the target: the default, http://localhost:3000, is Grafana in the LiteLLM stack.
  • For load tests, add -save-conversations=false: saving every turn to disk is slow.

macOS: if the log shows failed to load native plugin with “chained fixups”, rebuild the plugins with these linker flags, then start the proxy again.

shell
for p in simhash jaccard velocity error_acc entropy policy; do
  go build -buildmode=plugin \
    -ldflags="-linkmode=external -extldflags=-Wl,-no_fixup_chains" \
    -o plugins/$p.so ./plugins/$p
done
tests
go test ./...
go test -race ./...
go vet ./...
go test -run '^$' -bench . -benchmem ./stream

Full chain

Agent → Circuit Breaker :8080 → LiteLLM :4000 → providers. Start the LiteLLM stack, put the proxy in front of it, then call a model through the proxy.

shell
# Terminal 1: gateway + its observability
cd AI-Monitoring && docker compose up -d

# Terminal 2: the circuit breaker in front of LiteLLM
cd AI-Ciurcit-Breaker
TARGET_URL=http://localhost:4000 ./circuit-breaker

# Terminal 3: call a model through the proxy
export LITELLM_MASTER_KEY=sk-1234   # use the value from your .env
curl -sS http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Session-ID: demo-agent-1" \
  -d '{"model":"qwen3.6-27b","messages":[{"role":"user","content":"Say hello in five words."}]}'

Watch a breaker trip without spending tokens: 15 parallel requests on one session. About ten pass in that second; the rest come back 429 with Retry-After: 5 and HIGH_RPS_DETECTED.

shell
seq 1 15 | xargs -P15 -I{} curl -s -o /dev/null -w "%{http_code}\n" \
